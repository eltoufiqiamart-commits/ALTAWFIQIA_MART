# تقرير التحصين النهائي — EL TAWFIKIA MART

تاريخ المراجعة: 2026-09-16 — كود المرجع: نهاية سلسلة الترحيلات `0019_preview_coupon.sql`.

هذا التقرير يصف ما تم تنفيذه والتحقق منه فعليًّا، وما هو مطلوب قبل وبعد النشر.
**لا يوجد نظام «آمن 100%»**: الأمن طبقات (دفاع متعمق)، وهذا التقرير لا يُعدّ
اختبار اختراق بشريًّا ولا ضمانًا بعدم وجود ثغرات غير مكتشفة.

التصنيف: **مكتمل ومُختبَر محليًّا** / **مكتمل بانتظار اختبار حي** / **مخاطر/مهام متبقية**.

## A) المصادقة والجلسات (Auth)

- تسجيل الدخول/الاشتراك/استعادة كلمة المرور عبر Supabase Auth؛ البريد/كلمة المرور
  مع تحقق Zod مركزي (كلمة مرور ≥8 أحرف، بريد مصري للهاتف).
- معالجة تأكيد البريد عبر `/auth/confirm` (Route Handler) + مساعد إعادة توجيه
  آمن واحد `src/lib/safe-redirect.ts` يمنع فتح التحويل المفتوح (open redirect).
- تحديث الجلسة في الميدلوير مع عدم الاعتماد عليه كحد أمني وحيد؛ كل صفحة/إجراء
  محمي يعيد التحقق خادميًّا.
- حدود معدل على: تسجيل الدخول (8/دقيقة)، الاشتراك (6/10د)، استعادة كلمة المرور
  (4/10د)، الدفع (12/10د)، المراجعات (10/10د)، التواصل (5/10د)، الرفع (40/دقيقة).
- **مطلوب بعد النشر**: إعداد SMTP حقيقي (أو قرار واعٍ بإيقاف تأكيد البريد)،
  وضبط Site/Redirect URLs على رابط الإنتاج.

## B) التفويض والأدوار (RBAC)

- الأدوات المركزية: `requireUser`, `requirePermission`, `adminContext`,
  `adminPageContext`, ومصفوفة الصلاحيات `src/lib/permissions.ts`.
- كل عمليات الإدارة (منتجات، مخزون، طلبات، دفعات، مرتجعات، كوبونات، تصنيفات،
  محتوى، موردين، إعدادات، أدوار) تمر عبر صلاحية محددة لكل إجراء + حد معدل.
- لا يوجد أي رابط «دخول الأدمن» في الواجهة العامة؛ الحماية لا تعتمد على إخفاء
  المسار (الميدلوير + تخطيط `/admin` + كل إجراء).
- صفحات الإدارة تعيد توجيه الزائر إلى تسجيل الدخول وغير المصرح له إلى `/403`.

## C) عزل البيانات وRLS وRPC

- RLS مفعّل على كل الجداول الحساسة؛ العملاء لا يرون تكلفة/ربح/موردين
  (اختيار أعمدة صريح، لا `SELECT *` عام، لا إخفاء عبر CSS).
- جداول `coupons` و`coupon_usage` غير قابلة للقراءة للعملاء؛ المعاينة فقط عبر
  RPC ضيقة `preview_coupon(text, bigint)` تُرجع حكمًا / تسعيرًا مصغّرًا
  (الترحيل `0019`، `SECURITY DEFINER` + `search_path=public` + منح صريح).
- الترحيل `0018` ألغى الصلاحيات الافتراضية على الدوال الداخلية؛ أي RPC عميل
  جديدة يجب أن تُمنح صراحةً.
- **مكتمل بانتظار اختبار حي**: `docs/SECURITY-TESTS.sql` (10 أجزاء، كلها داخل
  معاملات rollback) يحتاج تشغيله في Supabase SQL Editor بمعرفي عميلين حقيقيين
  والتأكد أن كل النتائج PASS. تعذّر تشغيله محليًّا لعدم وجود مشروع حي/psql.

## D) مركزية المال والتسعير (مصدر الحقيقة هو الخادم)

- كل المبالغ بوحدات صحيحة (`bigint` بالقرش، لا عوامات).
- الخادم يعيد حساب: الإجماليات، المخزون، الشحن حسب المحافظة، رسوم COD 1%،
  خصم الدفع المسبق (3% تحت 3,000 ج.م، 5% عند 3,000 فأكثر) داخل RPC
  `place_order`؛ العميل لا يُرسل أسعارًا ولا يُوثَق بكلامه.
- تفسير العتبة/النسب مركزي في دوال التسعير (لا ازدواجية في الواجهة).
- لقطة تسعير ثابتة (`pricing_snapshot`) وعنوان ثابتة (`address_snapshot`) تُخزَّن
  على الطلب فور إنشائه (الطلبات والسجلات المالية immutable).

## E) الطلبات والدفعات والمخزون (Idempotency & Atomicity)

- مفتاح عديمة التأثير لكل طلب: `unique(user_id, idempotency_key)`؛ إعادة الإرسال
  تُرجع نفس الطلب بعلامة `duplicate` ولا تُنشئ نسخة (تمت مراجعة الكود ساكنًا).
- حجز وخصم المخزون ذرّي داخل `place_order` (حلقة فحص وخصم، وإرجاع/rollback عند
  أي عطل).
- التحقق من الدفعة اليدوية (`admin_verify_payment`) والمرتجعات وانتقالات الحالة
  كلها RPC انتقالية بحراسة حالة (لا يمكن تكرار الموافقة).
- إلغاء تلقائي للطلبات المدفوعة مسبقًا المعلّقة بعد 24 ساعة مع تحرير المخزون
  وإعادة الكوبون عبر `/api/cron/maintenance` المحمي بـ`CRON_SECRET`
  (تم التحقق: 401 بدون/بسر خاطئ، والتنفيذ بسر صحيح).
- التأكيد النهائي لمسار الشراء حتى نجاح الدفع يحتاج تشغيلًا حيًّا (UAT).

## F) الكوبونات

- قفل الصف `SELECT ... FOR UPDATE` يمنع تجاوز `total_usage_limit` و
  `per_user_limit` تحت التزامن؛ الاستبدال والاستخدام في نفس معاملة الطلب.
- كوبون مُرسَل بلا استحقاق يُرفض صراحةً (لا يُتجاهَل صامتًا).
- لا قراءة عامة لجدول الكوبونات؛ المعاينة عبر `preview_coupon` فقط.

## G) الإيصالات والرفع والتخزين

- Bucket عام `products` (صور مُعاد ضغطها WebP خادميًّا عبر sharp) وBucket خاص
  `private` للإيصالات (لا قراءة مباشرة).
- مسار الإيصال مفروض قاعديًّا: `receipts/<auth.uid()>/<uuid>.(jpg|png|webp|pdf)`
  (الترحيل `0016`) + تحقق TypeScript قبل الرفع + تحقق magic bytes
  (ffd8ff / PNG / RIFF…WEBP / `%PDF-`) + فك الصور بـsharp مع حد بكسلات
  40 ميجابكسل (مضاد قنابل فك الضغط) + حد حجم.
- الصور العامة تُعاد ترميزها WebP (يُجرّد أي محتوى مضمَّن)؛ لا رفع مبني على
  نوع الملف الذي يرسله العميل.
- عرض الإيصال: مصادقة → صلاحية `payments.verify` → جلب المسار من الخادم →
  رابط موقّع عمره 10 دقائق فقط؛ الصفحات الخاصة `no-store`.
- ملاحظة معروفة: ملفات PDF تُعرَض inline عبر الرابط الموقّع (لا تُجبَر على
  التنزيل)؛ المخاطر محدودة لأن الواقي هو صلاحية الإدارة + قصر عمر الرابط.

## H) حدود المعدل وإساءة الاستخدام

- الحدود في قاعدة البيانات (`check_rate_limit`) فتعمل عبر كل نسخ Vercel
  بلا حالة في الذاكرة، وتفشل بشكل مغلق (fail-closed) عند عطل القاعدة.
- مفاتيح المحدد تجمع هوية المستخدم وIP. على Vercel يُستبدَل الترويس
  `X-Forwarded-For` بالكامل عند الحافة لمنع التزييف
  ([وثائق Vercel الرسمية](https://vercel.com/docs/headers/request-headers))؛
  عند التشغيل الذاتي خادمًا لـ Vercel يصبح IP قابلًا للخداع (قيد موثّق).
- التنظيف ذاتي للجداول + وظيفة كرون يومية (حد مجاني على Hobby).

## I) الترويسات وCSP والنقل

- CSP صارم: بلا أي مزوّد طرف ثالث؛ لا نصوص خارجية، `frame/object-src none`،
  `base-uri/form-action/frame-ancestors self/none`، و`upgrade-insecure-requests`
  في الإنتاج، HSTS مع preload، X-Frame-Options DENY، nosniff،
  Referrer-Policy، Permissions-Policy.
- ملاحظة فحص محلي: على `http://localhost` يسبب `upgrade-insecure-requests`
  خطأ SSL للجلب الاستباقي لمسارات auth — سلوك صحيح على إنتاج https وليس عيبًا.
- لا تتبّع، لا خطوط خارجية، لا نصوص تتبّع.

## J) التسريب والتخزين المؤقت للبيانات الخاصة

- كل مسارات `/api/*` ترسل `Cache-Control: no-store`؛ الصفحات الخاصة
  (الحساب/الدفع/الإدارة) `noindex, no-store` عبر الميدلوير.
- فحص بناء نظيف: صفر سلاسل JWT/أسرار في `.next/static`، لا أثر لمفتاح
  service_role في حزم المتصفح، لا ملف `.env` داخل نتاج البناء النظيف،
  `npm audit`: 0 ثغرات.
- مفتاح service_role موجود فقط في ملفات `server-only`؛ كل وحدة إدارة
  تستورد `server-only`.

## K) التحقق من الإدخال، إعادة التوجيه، معالجة الأخطاء

- Zod مركزي لكل مدخلات العملاء (`src/lib/validation.ts`)؛ الأخطاء تُترجم إلى
  رسائل عربية آمنة (`arabicError`) بدون كشف تفاصيل داخلية.
- مساعد إعادة توجيه آمن وحيد؛ روابط البانرات/المحتوى الإداري تمر بفحص
  `safeInternalHref`.
- نتائج بحث/مركبات عامة: طول محدود، نتائج محدودة العدد، RPC، فشل ناعم.

## L) SEO

- خريطة موقع حقيقية متعددة الملفات عبر Route Handlers:
  - `/sitemap.xml` — `<sitemapindex>` يحيل إلى صفحات + شظايا منتجات؛
  - `/sitemap/pages.xml` — الثابتة + الأقسام المنشورة + الماركات النشطة
    (تُخدَم حتى عند فشل القاعدة)؛
  - `/sitemap/products/[id]` — 1,000 منتج/شظية مع `lastmod`، سقف 50 شظية
    (50 ألف منتج)، ومعرّفات غير صحيحة/خارج النطاق = 404 نصّي.
  - النوع `application/xml`، التخزين `s-maxage=600, stale-while-revalidate=86400`.
- `robots.txt` و`manifest.webmanifest` وJSON-LD منتج/قائمة خبز/منظمة، وبيانات
  Open Graph، وعناوين/وصف لكل صفحة.

## M) الجوال، RTL، الوصولية (نتائج فعلية بمتصفح Chromium)

- فحوصات Playwright داخل `qa/` (موثّقة في `qa/README.md`).
- مصفوفة الجوال 320/360/375/390/414 والديسكتوب 768/1024/1280/1440/1920:
  **صفر تمرير أفقي** على كل الصفحات، و`dir=rtl` و`lang=ar` دائمًا.
- أهداف اللمس: كل الأزرار/الروابط التنقّلية ≥ 36px (عُثر على قيم 16–32px
  وصُحّحت: زر بحث الديسكتوب، روابط الفوتر، روابط المصادقة، روابط «عرض الكل»،
  صف حالة الكتالوج الفارغة الذي كان يسبب تمريرًا أفقيًّا 42px على 320).
- فحص الوصولية على 19 صفحة عامة: **صفر ملاحظات** (تدرّج عناوين h1→h2→h3،
  حقل واحد h1، تسمية كل الحقول، تسمية الأزرار/الروابط، alt للصور).
- استثناء الاتفاقية: الهيدر الرئيسي LTR بصريًّا (شعار يسار، بحث وسط،
  حساب/قلب/سلة يمين) مع هيدر جوال مخصص وشريط تنقل سفلي بارتفاع 60px.

- نسخ الإصدارات مثبّتة: Next 15.5.25، React 18، sharp 0.35.4؛ لا ترقية لـ

- **Node 22.x مطلوب** (`engines`)؛ التطوير المحلي جرى على Node 20 (تظهر
  تحذيرات إهمال من supabase-js لكنه يعمل).
- تحقق مسار دخان كامل: 34 مسارًا عامًّا (200/307 للخاص/404 المفقود)،
  admin/cron يرفضان غير المصرح (401)، خريطة الموقع بكل أنواعها، واختبار

- الترحيلات 0001–0019 تعيد بناء قاعدة فارغة كاملة؛ وثائق: `DEPLOYMENT.md`

  `.env.example`.

## O) مخاطر ومهام متبقية (لا تُعتبر مكتملة)

1. **تشغيل `docs/SECURITY-TESTS.sql` على مشروع Supabase حي** بمعرفي عميلين
   ومعالجة أي FAIL — أهم بند متبقٍّ.
2. **اختبار رحلة شراء كاملة يدويًّا على بيئة staging** (سلة → دفع → تأكيد دفعة
   → توصيل → إرجاع)؛ تعذّر آليًّا بدون قاعدة حية.
3. اختبار بصري لمناطق الحساب/الدفاع/الإدارة بعد تسجيل الدخول لم يُجرَ آليًّا
   (الجوال والديسكتوب للواجهة العامة فقط هما المُغطَّيان بالكامل).
4. إعداد SMTP/تأكيد البريد وإعدادات Auth URL قبل الإطلاق.
5. صورة الهيرو `photo1` تحتوي نصًّا مضمّنًا «توصيل في أقل من 24 ساعة» وهو ما
   يخالف سياسة الصياغة المعتمدة («توصيل سريع حسب الموقع وظروف الطلب»)؛
   لم تُعدَّل الصورة التزامًا بعدم المساس بها — قرار مطلوب من المالك
   (إعادة تصميم الصورة أو إزالة النص منها).
6. لا اختبار اختراق بشري/آلي متقدم (مثل OWASP ZAP) نُفّذ؛ يُنصح به قبل
   المعاملات الحقيقية.
7. القيود المعمارية للباقة المجانية: نوم المشروع/حدود تخزين 1GB/حد معدل
   الرسائل؛ يجب مراقبتها بعد الإطلاق، وضبط نسخ احتياطي دوري حسب `BACKUP.md`.
8. عند التشغيل الذاتي خارج Vercel: ثقة IP غير مكفولة (راجع H)، وتلزم إزاحة
   بروكسي موثوق؛ النشر الرسمي المدعوم هو Vercel.
9. يُفضَّل فحص ملفات PDF المرفقة باحتياط تشغيلي (إجبار التنزيل ممكن لاحقًا
   دون كسر التدفق).
10. شعار الموقع والهيرو مستخدمان كما هما تمامًا دون إعادة رسم أو تحويل ذكاء
    اصطناعي (ضُغِط الهيرو تقنيًّا فقط إلى WebP).

### ملخص أوامر التحقق

```bash
npm ci
npm run typecheck && npm run lint && npm run lint:admin
NODE_OPTIONS="--max-old-space-size=1200" npm run build
# ثم على مشروع Supabase حي: تشغيل docs/SECURITY-TESTS.sql بالكامل
```

أي تعديل مستقبلي على سياسات RLS أو دوال RPC يجب أن يُتبع بإعادة تشغيل
`SECURITY-TESTS.sql` قبل النشر.
